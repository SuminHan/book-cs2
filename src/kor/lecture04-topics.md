# Topics Covered

## Problem 1: 3D → 2D 투영

큐브 더미는 3차원 0/1 리스트 `P`로 표현한다: `P[i][j][k] == 1`이면 위치
`(i,j,k)`에 큐브가 있다는 뜻이다(`i`: 위→아래, `j`: 뒤→앞, `k`: 왼쪽→오른쪽
방향의 좌표라고 생각하면 됨). 이 더미를 위/앞/오른쪽에서 내려다본 그림자가
각각 top/front/right view다 — 어느 방향에서든, 그 시선 방향으로 한 줄에
큐브가 하나라도 있으면 그 칸은 채워진 것으로 보인다.

`(i,j,k)`에 큐브가 있다는 것은 곧,

- `top[j][k] = 1` (위에서 봤을 때 그 자리가 채워져 보임)
- `front[i][k] = 1` (앞에서 봤을 때 그 자리가 채워져 보임)
- `right[i][j] = 1` (오른쪽에서 봤을 때 그 자리가 채워져 보임)

이 세 투영도 모두에 흔적을 남긴다는 뜻이다. 각 투영도는 세 좌표축 중
둘만으로 인덱싱되는 2차원 리스트임에 주의: top은 `(j,k)`, front는
`(i,k)`, right는 `(i,j)`.

## Problem 2: "역" 문제 — 투영도만 주어졌을 때

이제 반대 방향: top/front/right 세 투영도만 주어지고, 그것을 만들어낼 수
있는 큐브 더미 중 **큐브 개수가 최대인** 것을 찾아야 한다(애초에 그런
더미가 존재하지 않을 수도 있음).

**핵심 관찰**: `(i,j,k)`에 큐브가 있으려면 세 투영도 모두에 흔적이
남아야 한다(위 Problem 1). 즉,

> `P[i][j][k] == 1`이 가능하려면 `top[j][k] == front[i][k] == right[i][j]
> == 1`이 **반드시** 성립해야 한다.

따라서 이 조건을 만족하는 모든 `(i,j,k)`에 큐브를 채운 `P`가 — **존재할
수 있는 답들 중 가장 큰 후보**다. 어떤 답 `Q`가 세 투영도를 만족한다면,
`Q`에 있는 모든 큐브는 이 조건을 만족해야 하므로 `Q`는 `P`의 부분집합일
수밖에 없다. 즉 **`P`보다 큐브가 많은 답은 있을 수 없다.**

이제 이 `P`가 실제로 답이 되는지는 직접 확인하면 된다:

1. 조건을 만족하는 모든 `(i,j,k)`에 큐브를 채운 `P`를 만든다.
2. `P`의 실제 투영도(Problem 1의 함수들로 계산)가 입력으로 주어진
   top/front/right와 정확히 같은지 확인한다.
3. 같다면 `P`가 (최대 개수를 갖는) 답이다.
4. 다르다면(즉 `P`를 만들어도 투영도가 입력보다 "더 커져" 버린다면), 애초에
   그 투영도 조합을 만족하는 더미는 존재하지 않는다.

```python
def build(top, front, right):
    n = len(top)
    P = [[[0]*n for j in range(n)] for i in range(n)]
    for i in range(n):
        for j in range(n):
            for k in range(n):
                if top[j][k] == front[i][k] == right[i][j] == 1:
                    P[i][j][k] = 1
    return P

def countCubes(top, front, right):
    P = build(top, front, right)
    if topView(P) == top and frontView(P) == front and rightView(P) == right:
        return sum(sum(sum(row) for row in layer) for layer in P)
    return None
```

이 문제의 핵심은 "가능한 모든 큐브 배치를 하나하나 시도해서 큰 것을
고르는" 방식이 아니라, **"조건을 만족할 수 있는 유일한 후보를 논리적으로
구성한 뒤, 그것이 실제로 조건을 만족하는지만 확인**"하는 방식이라는
점이다 — 답이 존재한다면 그 후보가 곧 답이고, 존재하지 않는다면 그
후보조차도 조건을 못 만족한다.
