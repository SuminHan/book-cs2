Computer Science 2

Why Programming Matters

“이제 AI가 코드를 짜준다. 나보다 빠르고, 솔직히 나보다 더 잘 짠다. 그런데 내가 왜 프로그래밍 수업에 앉아 있어야 하지?”

정당한 질문이다. 그리고 “AI는 코딩을 잘 못한다“는 식으로 답할 생각은 없다. 못하지 않는다. 아주 잘하고, 매달 더 좋아지고 있다. 대신 다른 방식으로 답하려 한다 — 그래서 어떤 일이 새로 생겼는지 보여주는 방식으로.

What Changed

이진 탐색을 짜달라고 하면 즉시 나온다. 그리고 맞다. 10년 전엔 한 주치 수업 분량이었다. 지금은 4초. 그럼 무엇이 비싸졌는가?

병목이 옮겨갔다.

예전지금
어려운 부분코드를 쓰는 것코드를 판단하는 것
하루 100줄을 썼고, 그 100줄을 전부 이해하고 있었음 — 쓰려면 이해할 수밖에 없으니까1분이면 1000줄을 뽑음. 그중 몇 줄이나 이해하고 있나?

AI가 좋아진다고 이 일이 줄지 않는다. 오히려 늘어난다.

이건 이미 취업 시장에서 나타나고 있다: 신입과 인턴은 취업하기 더 어려워졌고, 빅테크의 평균 연차는 계속 올라가는 중이다 — 그런데 동시에 상위 테크 기업 채용은 1년 전보다 약 20% 증가했고, AI 엔지니어링 공고는 Apple, Google 등에서 50~100% 증가했다.1 둘 다 동시에 참이다. 왜? 예전에 입문하는 방법은 “작고 명확하게 정의된 과제를 줄 테니 구현해와라“였다. 그건 지금 AI가 가장 잘하는 일이다. 그 첫 계단이 사라졌다. 남은 일은 한 단계 위에서 시작한다 — 결정하고, 지시하고, 검증하는 일.

들어갈 때는 한국어든 영어든 사람의 언어를 쓸 수 있다. 하지만 돌아올 때는 답이 항상 코드다 — 출력에는 한국어 버전이 없다. 오직 코드가 있을 뿐이고, 그걸 읽을 수 있느냐만 남는다. 돌아온 것을 읽지 못한다면, 지시를 한 게 아니라 소원을 빈 것이다.

The Gap

“성적 계산기를 만들어줘“라고 시켜봤다. 이렇게 나왔다 — 깔끔하고, 읽기 쉽고, 잘 돌아간다:

def final_grade(scores, attendance_rate):
    average = sum(scores) / len(scores)
    if attendance_rate < 0.75:
        return "Fail"
    return "Pass" if average >= 70 else "Fail"

맞아 보인다. 돌아간다. 에러도 없다. 그런데 이 수업 기준으로는 틀렸다.

중요한 건 이 부분이다: 어디를 봐도 틀려 보이지 않는다는 것. 경고해주지 않는다. 그냥 조용히 잘못된 성적을 계산할 뿐이다.

세 가지를 알 수 없었다:

  • 어떤 학생이 병결로 시험을 못 봤다. 우리 규정은 인정점수에 80% 가중치를 — 공결이면 100%를 적용한다. 코드에는 둘 다 없다.
  • 어떤 학생이 Fail을 받고 재시험을 봤다. 어느 점수를 쓰는가? 코드는 재시험이란 걸 들어본 적이 없다.
  • 출석 3/4 미만 — 이게 모든 걸 덮어쓰는가, 아니면 먼저 확인하는가? 코드는 찍었다. 그리고 우리와 다르게 찍었다.

“그럼 규정을 프롬프트에 넣으면 되잖아요!” — 맞다. 그런데 그렇게 하려면 뭐가 빠졌는지를 이미 알아챘어야 한다. 코드는 알려주지 않았다. 구멍을 보려면 읽는 수밖에 없었다.

The Trap

과제: 어떤 연도가 윤년이면 True를 반환.

def is_leap_year(year):
    if year % 4 == 0:
        return True
    else:
        return False

테스트해봤다: is_leap_year(2024) → True, 정답! 통과했다. 이대로 제출?

is_leap_year(1900)을 테스트해보면 — 기대값은 False(1900년은 윤년이 아니었다)인데 실행 결과는 True. 왜: 진짜 규칙은 세 부분이다 — 4로 나누어떨어지고, 단 100으로 나누어떨어지면 제외하되, 그중 400으로 나누어떨어지면 다시 윤년. 코드는 첫 부분만 알고 있다. 1900은 100으로는 나뉘지만 400으로는 안 나뉘므로 윤년이 아니다.

버그는 처음부터 거기 있었다. 테스트가 그쪽을 안 봤을 뿐이다. 테스트를 통과했다는 건 맞다는 뜻이 아니다. 어떤 입력이 이걸 깨뜨리는지 고르는 것 — 그게 실력이다. 그리고 그건 아무도 대신 해줄 수 없다.

같은 패턴이 실제로도 있었다: NASA의 Mars Climate Orbiter는 10개월을 날아갔고, 화성 상공 약 150km에 안착할 예정이었으나 실제로는 57km로 진입해 대기권 한복판에서 부서졌다 — 한 팀은 추력 값을 파운드힘(lbf) 단위로 넘겼고, 받는 팀은 그걸 뉴턴(N)으로 읽었다. 1 lbf = 4.45 N이라 모든 궤도 수정이 4.45배씩 어긋난 채로 10개월이 지났다. 손실 1억 2500만 달러. 그 코드는 한 줄도 빠짐없이 완벽하게 돌아갔다. 그 숫자가 무슨 뜻인지 아무도 확인하지 않았을 뿐이다.

Your Job

1950년 튜링은 “기계가 생각할 수 있는가?“라고 물었고 — 답하기를 거부했다. 대신 시험으로 바꿨다: 사람 심판이 양쪽에 질문을 던지고 그 답이 말이 되는지 판단한다. 컴퓨터의 맨 처음 설계에 이미 질문을 던지는 사람이 의자에 앉아 있었다. 그 의자는 끝내 자동화되지 않았다.

이 과목의 교과 핵심역량 네 가지 — 그리고 방금 각각을 어디서 만났는지:

  • Fundamental Programming & Problem-Solving — 돌아온 코드를 읽고, 그게 실제로 무슨 일을 하는지 이해하기
  • Logical Thinking & Analytical Skills — 어떤 입력이 이걸 깨뜨릴지, 깨지기 전에 알기
  • Communication & Collaboration — 수업 시간에 문제를 같이, 소리 내어 푸는 이유
  • Ethical Use of AI & Responsible Attitude — 도구는 쓰되, 답에 대한 책임은 내가 진다. “AI가 짰는데요“는 변명이 되지 않는다.

기계보다 코드를 빨리 치려고 여기 온 게 아니다. 원하는 것을 정확히 말할 수 있고, 돌아온 것을 읽을 수 있고, 어떤 입력이 깨뜨릴지 아는 사람이 되기 위해서다. 그래서 수업은 이렇게 운영된다: 수업 시간에 문제는 AI 없이, 다 같이, 손으로 푸는 게 원칙이다. AI를 쓰는 게 부정행위라서가 아니라 — 기계가 대신 해주는 능력은 내 것이 되지 않기 때문이다.

평생 계산기를 쓸 것이다. 그래도 산수는 손으로 배웠다.

Problem Set

필수 문제

1. deleteThree(L) — 리스트 L에서 3을 모두 제거한 리스트를 반환.

def deleteThree(L):
    M = []
    for i in range(len(L)):
        if L[i] != 3:
            M.append(L[i])
    return M

print(deleteThree([2,5,7,3,2,8,3,3]))  # [2,5,7,2,8]
print(deleteThree([2,3,7,3,2,8,3,3]))  # [2,7,2,8]
print(deleteThree([3,3,7,3,2,8,3,3]))  # [7,2,8]

새 리스트를 만들 땐 []로 초기화한 후 M.append(·)로 하나씩 붙여나가면 된다.

2. delete(L, e) — 리스트 L에서 정수 e를 모두 제거한 리스트를 반환. (1번과 같은 패턴, 조건만 e로 일반화)

3. kthSmallest(L, k) — 정수 리스트 L에서 k번째로 작은 값을 반환 (1 ≤ k ≤ len(L)).

L.sort()를 쓰면 L 자체가 정렬되고 반환값은 None이라는 점에 유의. k번째로 작은 원소는 정렬 후 L[k]가 아니라 L[k-1].

4. same(L1, L2) — 두 리스트가 (순서 상관없이) 같은 원소를 같은 개수만큼 가지면 True.

L1 == L2는 순서까지 완전히 같아야 True. 정렬 후 비교하면 순서를 무시할 수 있다.

5. makeSet(L) — 리스트 L의 원소를 중복 없이 정확히 하나씩만 포함한, 정렬된 리스트를 반환.

1, 2번과 유사한 형태 — 지금까지 만든 M에 아직 없는 원소일 때만 append. x in L / x not in L로 포함 여부 확인.

6. sortId(L) — ID와 이름이 번갈아 나오는 문자열 리스트 L을, 학생 ID 기준으로 정렬해서 반환.

ID = L[::2]로 짝수 인덱스만 뽑아낼 수 있다. y = L.index(x)는 L에서 x가 처음 등장하는 인덱스(없으면 에러).

7. countA(s) — 문자열 s에서 "A"의 개수를 반환.

def countA(s):
    counter = 0
    for i in range(len(s)):
        if s[i] == "A":
            counter += 1
    return counter

print(countA("AbAA"))          # 3
print(countA("bcdAAAdfAA"))    # 5
print(countA("abc"))           # 0

8. countChar(s, c) — 문자열 s에서 문자 c(길이 1인 문자열)의 개수를 반환. (7번의 일반화)

9. reverse(s) — 문자열 s를 뒤집은 문자열을 반환.

""로 초기화한 뒤 +로 한 글자씩 이어붙이는 패턴: r = r + ??. s의 뒤쪽 문자부터 r에 붙여나가면 된다.

10. delete(s, c) — 문자열 s에서 문자 c를 모두 제거한 문자열을 반환.

9번과 비슷한 형태로, 앞에서부터 r에 붙이되 s[i] != c일 때만 붙이면 된다.

11. replace(s, c, to) — 문자열 s에서 문자 c를 전부 to로 교체한 문자열을 반환.

s[i] == c일 때는 s[i] 대신 to를, 아니면 s[i]를 그대로 붙인다.

12. firstStr(s1, s2, s3) — 세 문자열 중 사전순으로 가장 앞서는 문자열을 반환.

File I/O

  • open(filename, "r").read().split() — 파일 내용을 전부 읽어서 단어 단위로 쪼갠 리스트로 변환

  • Counter 패턴: 조건을 만족하는 원소의 개수 세기
  • Max/min 패턴: 조건을 만족하는 것 중 최댓값/최솟값(+ 그 대상) 유지
  • 문자열 슬라이싱으로 부분 문자열 검사(s[i:i+5:2] 등)

Problem Set

필수 문제

1. inOrder(filename) — 파일의 모든 단어가 사전순으로 정렬되어 있는지 여부.

def inOrder(filename):
    words = open(filename, "r").read().split()
    n = len(words)
    for i in range(n - 1):
        if words[i] > words[i + 1]:
            return False
    return True

print(inOrder("dictionary.txt"))   # True
print(inOrder("dictionary2.txt"))  # False

“for all” 패턴. range(n)이 아니라 range(n-1)을 써야 마지막 인덱스에서 words[i+1]이 범위를 벗어나지 않는다.

2. isPalindrome(s) / maxPalindrome(filename) — isPalindrome은 문자열이 회문(앞뒤로 읽어도 같음, 예: "deified")인지 판정. maxPalindrome은 파일에서 가장 긴 회문을 반환(동점이면 먼저 나온 것).

isPalindrome은 “for all” 패턴(s[i]와 s[n-1-i] 비교). maxPalindrome은 max 패턴이되 “가장 긴 길이“가 아니라 “가장 긴 회문 단어” 자체를 유지해야 하므로 maxlen뿐 아니라 maxword도 같이 갱신.

3. isAbecedarian(s) / countAbecedarian(filename) — abecedarian은 모든 글자가 알파벳 순서로 나타나는 단어(예: "aaabb", "acorsy"). isAbecedarian은 판정 함수, countAbecedarian은 파일에서 그 개수를 센다.

isAbecedarian은 “for all” 패턴, countAbecedarian은 counter 패턴.

4. disjoint(s1, s2) — 두 문자열이 겹치는 글자가 하나도 없으면 True.

print(disjoint("ace", "a"))          # False
print(disjoint("aurora", "steel"))   # True
print(disjoint("elephant", "long"))  # False

“for all” 패턴. s1[i] in s2로 각 글자의 포함 여부를 확인.

5. countWordWithE(filename) — 파일에서 알파벳 "e"를 포함한 단어의 개수. Counter 패턴.

3. secret(n, t, T, x, s) — 다항함수를 이용한 비밀 분산(secret sharing) 문제. 딜러가 정수 비밀 \(S\)를, \(\ell\)개의 그룹으로 나뉜 \(N\)명에게 각각 정보 조각을 나눠준다. 조건을 만족하는 인원(전체 \(T\)명 이상, 각 그룹에서 \(t_i\)명 이상)이 모이면 다항식 값들로부터 \(S\)를 유일하게 복구할 수 있고, 조건을 만족하지 못하면 복구할 수 없다. 모인 사람들의 정보 s(모이지 않은 사람은 None)와 공개된 좌표 x로부터 비밀 S를 복구하는 함수를 작성.

Shamir’s Secret Sharing의 일반화 버전. 각 그룹 \(i\)에 대해 다항함수 \(f_i(x) = g(i) + \sum a_{i,j}x^j + \sum b_j x^{t_i+j-1}\)을 구성해 정보를 나눠주며, 충분한 정보가 모이면 이 다항함수들을 Gaussian elimination으로 복원해 \(S = g(0)\)을 얻는다. (부동소수점 오차를 피하려면 8주차에서 다룰 유리수 기반 Gaussian elimination을 사용.)

        dy = self.y - p.y

    def add(self, p):                  # pure function

    while b > 0:
